# RFC 0003: quickdraw 5.0

Status: draft for owner review, 2026-10-02. Baseline: 4.1.0 (`main` at `f767f68`).
Companion: `0003-v5-audit.md` (the audit and rationale behind every choice here).

This is the design record builders implement from. Where a card's plan and this document disagree, this document wins; fix the card.

## 0. Decisions already made

| Decision | Choice | Why |
|---|---|---|
| Scope | Rebuild `BaseService`, `ServiceRegistry`, the wire protocol and the client hooks. Keep the concepts, Socket.IO, TanStack Query and Prisma | The redesign changes their foundations; the concepts are what apps and agents know |
| Service authoring | Declarative `defineService(contract, {...})` object, no classes | Owner decision. The compiler checks every contract method is implemented; lint, docs and MCP generation read literals |
| Wire | Clean break from 4.x, plus a legacy shim for 4.x request/response callers | Owner decision. Removes capability negotiation |
| Kits in 5.0 | Read/write, search, sharing and membership, admin, presence and streams, auth routes | Owner decision |
| Transport | Socket.IO 4.8.x | Only option with rooms, acks, adapters and React Native support in one package |
| Schemas | Standard Schema for validation; Zod 4.2 or later only where JSON Schema is generated | Existing Zod 3.25 schemas keep working during migration |
| Database | Prisma 7 through a structural adapter; Drizzle later behind the same interface | Every consumer is on Prisma 7; the framework cannot import generated Prisma types |
| Emit source | Tracked writes in the app process. Not `LISTEN/NOTIFY`, not logical replication | `NOTIFY` serializes commits; replication slots add operations risk |
| Package name | `@fitzzero/quickdraw-core` stays. Lint and skills become separate packages | Least churn for consumers |
| Service and level names | Unchanged on the wire and in stored data (`"taskService"`, `"Public" \| "Read" \| "Moderate" \| "Admin"`) | `User.serviceAccess` and JSON access lists store these strings |

## 2. Contract

One contract per service, in the app's shared package. It is plain data plus schemas, so the client can import it without server code.

```ts
import { defineContract, query, mutation } from "@fitzzero/quickdraw-core";

export const task = defineContract("taskService", {
  entity: taskSchema,                       // full shape; must contain `id: string`
  projections: { card: taskCardSchema },    // named lean shapes; "entity" is implicit
  fields: { internalNotes: "Admin" },       // minimum level to receive a field (entity only)
  methods: {
    get:    query({ input: z.object({ id: z.string() }), output: "entity" }),
    rename: mutation({ input: renameSchema, output: "entity" }),
    stats:  query({ input: statsInput, output: statsSchema, watch: { collection: "byProject", scope: (i) => i.projectId } }),
  },
  collections: {
    byProject: {
      scope: "projectId",
      item: "card",
      order: [["ordinal", "asc"], ["id", "asc"]],
      index: ["status", "ordinal", "assigneeId"],
      views: { mine: (row, who) => row.assigneeId === who.userId },
    },
  },
  streams: {}, channels: {}, events: {},
});
```

Rules:

- Every method is a `query` or a `mutation`. The kind drives sharing, cancellation, concurrency caps, the HTTP verb, the MCP read-only hint and which client hook exists.
- `input` and `output` are required. `output` is a schema, or the name of a projection (`"entity"`, `"card"`), optionally wrapped: `nullable("entity")`, `listOf("card")`.
- Schemas are any Standard Schema. A contract that feeds MCP or the admin kit must use schemas that implement Standard JSON Schema (Zod 4.2 or later).
- Reserved member names, rejected at definition time for methods and collections alike: `subscribe`, `unsubscribe`, `call`, `then`, `useEntity`, `useEntities`, `admin`, and any name starting with `$`. Methods and collections share one namespace, because the client exposes both as `qd.<service>.<name>`.
- `entity` is optional. A contract without one is an RPC-only service (the 4.x `BaseRpcService` case): it has no projections, `fields`, collections or `"entity"` outputs.
- Every projection, like the entity, must contain `id: string`; collection items and entity frames are keyed by it.
- Only a `query` may `watch`. `watch.scope(input)` receives the caller's input and returns the scope id.
- Standard Schema exposes validation only, never a schema's keys. Where the framework needs keys, it reads Standard JSON Schema (Zod 4.2 or later): a projection's `select` (section 6), admin field metadata (section 12.4) and MCP tool schemas (section 10). A projection whose schema cannot provide JSON Schema must declare `keys` in the service's `project` option, or the service fails at definition time. That check runs where the capability is consumed (`hasJsonSchema`), not in `defineContract`, which cannot know who will read the contract.
- `index` fields are fields of the collection's item projection; a view receives `Pick<Item, "id" | IndexField>`. `order` is required and names entity columns.
- Inference helpers: `InputOf<C, M>` (what the caller passes), `ParsedInputOf<C, M>` (what the handler receives after the schema ran), `OutputOf<C, M>`, `EntityOf<C>`, `ProjectionOf<C, P>`, `ItemOf<C, K>`, `ScopeOf<C, K>`, `IndexRowOf<C, K>`, `ViewName<C, K>`, and the rest exported from the package root.

## 3. Server

```ts
// apps/api/src/quickdraw.ts
export const qd = initQuickdraw<{ db: AppPrisma; principal: AppPrincipal }>();

// apps/api/src/services/task.ts
export const taskService = qd.defineService(task, {
  model: "task",
  access: inherit({ from: project, via: "projectId" }),
  writes: ["taskLabel"],                    // other models this service may write
  affects: [{ service: task, id: (row) => row.parentTaskId }],
  methods: {
    rename: {
      access: { entry: "Moderate" },
      handler: ({ input, db }) => db.task.update({ where: { id: input.id }, data: { title: input.title } }),
    },
    ...queries(deps),
  },
});

// apps/api/src/index.ts
const server = qd.createServer({ app, services: [taskService, projectService], db: prisma, auth: {...} });
```

- `defineService` is typed so `methods` must implement exactly the contract's methods. Kits (section 12) contribute both contract entries and handlers.
- `initQuickdraw<{ db; principal; context?; contracts? }>()`. `contracts` is the app's contract map type; it types `qd.caller` and `ctx.services`, which avoids a circular type from the services themselves. `qd.createDispatcher` builds the dispatcher the server factory wraps.
- Handler argument: `{ input, ctx, db }`. For a method whose output is a projection, the handler returns the database row (section 6 projects it; the handler's return type accepts the row shape, with `Date` values, not the wire shape).
  - `db` is the tracked database client (section 5), typed as the app's own client.
  - `ctx`: `principal` (`userId`, `kind`, `claims`, `serviceAccess`), `signal` (`AbortSignal`), `log`, `requestId`, `transport` (`"socket" | "http" | "mcp" | "internal" | "legacy"`), `touch()`, `services` (typed in-process callers for other services), and `rooms` for stream and presence joins.
  - Apps extend `ctx` once through `initQuickdraw({ context: (base) => ({...}) })`. This replaces overriding `defineMethod`.
- A handler that returns a database row for a projection output is projected by the framework (section 6). It does not build the wire shape by hand.
- Services without a model omit `model` and `access` and may only use `"public"`, `"authenticated"`, `{ service }` or `custom` access.
- `createServer` accepts an existing Express app and HTTP server (an `httpServer` without its `app` is refused unless `http: false`). It owns socket auth, the `user:{id}` room, the hello frame, disconnect cleanup and graceful shutdown; `close()` waits for calls in flight, bounded by `shutdownTimeoutMs`. It never calls `process.exit`; signal handlers are opt-in. There is no default CORS origin (4.1 defaulted to `*`); cross-origin clients that use long polling need `cors` passed. MCP custom tools default to `access: "authenticated"`. `authenticate` takes one request object (`{ transport, auth, headers, socket | req }`) for both transports and returns a principal, a user id string, or nothing for anonymous. The socket rate limiter is on by default (600 events per minute per socket, also `createRateLimiter()`'s default without `maxRequests`; 4.x had 100; `qd:ch`, `qd:cancel` and the subscription events are excluded).

### Errors

Handlers throw `QuickdrawError(code, message, data?)`. Anything else becomes `INTERNAL` with a generic message; the original is logged.

| Code | HTTP | Meaning |
|---|---|---|
| `UNAUTHENTICATED` | 401 | no principal |
| `FORBIDDEN` | 403 | access denied |
| `NOT_FOUND` | 404 | unknown service, method or row |
| `CONFLICT` | 409 | unique or state conflict |
| `VALIDATION` | 422 | input failed its schema; `data.issues` lists paths |
| `RATE_LIMITED` | 429 | limiter or queue overflow; `data.retryAfterMs` |
| `CANCELLED` | 499 | caller cancelled |
| `TIMEOUT` | 504 | handler exceeded its time limit |
| `INTERNAL` | 500 | everything else |

`VALIDATION` carries `data.issues` as `{ path: (string | number)[]; message: string }[]`; the dispatcher converts Standard Schema issues into that shape. `INTERNAL` reaches the wire with a generic message and no `data`, even when a handler throws it deliberately.

Framework writes never swallow errors. A known Prisma unique violation maps to `CONFLICT`, a missing row to `NOT_FOUND`.

## 4. Access control

Fail closed: a method with no `access` is a type error.

### 4.1 Method access forms

| Form | Passes when |
|---|---|
| `"public"` | always |
| `"authenticated"` | a principal exists |
| `{ service: L }` | the principal's service grant is at least `L` |
| `{ entry: L, id? }` | the principal's level on the row is at least `L` |
| `{ service: L1, entry: L2, id? }` | either of the two above |
| `{ scope: L, of: contract, id }` | the principal's level on a row of another service is at least `L` (for list and create methods) |
| `custom(fn)` | `fn(ctx, input)` resolves true |

- `id` defaults to `input.id`, and only type-checks when the input schema has an `id` key. There is no runtime sniffing of payloads.
- A service-wide `Admin` grant passes every check on that service (`adminBypass`, default true).
- A service-wide grant below `Admin` counts only where `service` is named. This fixes "a Read grant reads every row".

On a service with a policy, `defineService` refuses a method whose input may carry a top-level `id` under a form that checks no row (`"public"`, `"authenticated"`, or `{ service: L }` below `Admin`), since that would let everyone the form admits reach any row by its id (pack H). The input is read from its Standard JSON Schema with unrepresentable values written as `any`; `id` counts in the object or in any branch of a union or intersection. The way out is `rowless: true` on the method, or `rowless: [names]` on a kit, meaning every caller the form admits may reach any row. Not checked: inputs without Standard JSON Schema (Zod 3, a `todoSchema` without `keys`), inputs that are not an object at the top (a bare string id, arrays, records, `any`), an `id` only among a loose object's undeclared keys, and rows named by another key (`ids`, `taskId`, a nested `where.id`); `custom` forms and kit handlers that check the row themselves are exempt.

### 4.2 Policies

The service's `access` option says how a principal's level on a row is found.

| Builder | Level comes from |
|---|---|
| `owner(field)` | `Admin` when `row[field] === userId` |
| `jsonAcl(field, { owner? })` | the `[{ userId, level }]` JSON column, plus the owner |
| `members({ model, entry, user, level, levels? })` | a membership table row |
| `inherit({ from, via })` | the level on the parent row in another service |
| `anyOf(...)` | the highest level any policy grants |
| `resolver({ levelsFor, where? })` | custom code |

Every policy implements two functions:

- `levelsFor(principal, ids)` returns a level or null per id, in one batched query. A failed row lookup denies; it never falls back to treating the id as a scope id.
- `accessWhere(principal, level)` returns a filter fragment so list reads return only rows the principal can see.

Results are memoized per request. An optional `cacheMs` keeps them across requests; tracked writes to the membership model, the access column or the owner column evict the affected entries.

### 4.3 One policy, every surface

Method calls, entity subscriptions, collection scopes, list filtering, search and channels all use the same policy. Subscriptions authorize, then fetch, then join the room, in that order.

### 4.4 Revocation

Each live subscription records the row its access was derived from (its anchor). When a tracked write lowers or removes a principal's level on an anchor, the framework removes that principal's sockets from the affected rooms and sends `qd:revoked`; topic watches anchored there leave their rooms after one last `qd:changed`. A create is an access change too: sockets still in a deleted row's room (the tombstone rule) are re-authorized when that id is created again. In a multi-instance deployment the revocation is broadcast to every node, and a receiving node forgets its cached access reads for the change before re-resolving. The access-change and grants-refresh sinks run before the entity and collection emit sinks, so a flush that demotes a user never sends that flush's frames to the demoted subscriptions. A changed `serviceAccess` is pushed to the user's sockets instead of waiting for a reconnect.

## 5. Tracked writes

### 5.1 Unit of work

Every method call, and every `qd.run(fn)` block, runs inside a unit of work held in `AsyncLocalStorage`. The tracked client records each write into it:

`{ model, id, op: "create" | "update" | "delete", fields, before?, after? }`

`before` and `after` hold the model's interested columns (scope, membership and owner columns registered with `registerInterest`); `fields` is `["*"]` (`ANY_FIELD`) when the changed fields are unknown, as for a `ctx.touch`.

Writes inside `db.$transaction` are buffered separately and join the unit of work only when the transaction commits; a rollback discards them.

The unit of work awaits the handler's return value inside its scope. Prisma promises are lazy: they run where they are awaited, so a handler that returns `db.task.update(...)` without awaiting it would otherwise execute outside the scope and escape tracking. The same applies to `qd.run(fn)`. A write made with no active unit of work flushes on its own on the next tick, with a development warning suggesting `qd.run`.

### 5.2 Prisma operations

| Operation | How ids and scope values are obtained |
|---|---|
| `create`, `upsert` | from the result; `id` and scope columns are added to `select` when missing |
| `update` | from `where` or the result. If `data` touches a scope or membership column, the old values are read first with a narrow `select` |
| `delete` | from the result (Prisma returns the deleted row) |
| `createMany` | rewritten to `createManyAndReturn` |
| `updateMany` | rewritten to `updateManyAndReturn`; old scope values pre-read only when `data` touches them |
| `deleteMany` | ids and scope values pre-read with the same `where`, in the same transaction |
| nested writes in `data` | not tracked. Detected by shape (`create`, `connect`, `update`, `delete`, `set`, and similar keys); development warning; lint rule |
| `$executeRaw`, `$queryRaw` writes | not tracked. Lint rule requires `ctx.touch(model, ids)` |
| database cascades (`ON DELETE CASCADE`) | not tracked. Deleting a collection's anchor row closes its scopes automatically (section 7.2); other cascades need `ctx.touch` |

`ctx.touch(modelOrContract, ids, { removed? })` records writes the adapter cannot see, including database-level cascades.

### 5.3 Flush

Runs after the handler settles (success or failure), after the response has been sent:

1. Merge records per row to the row's final state: a row the unit certainly created and then deleted is dropped (it never existed outside the unit; an `upsert` that may have updated an existing row keeps its delete); a delete after an update is a `delete`; a create after a delete (the row exists again) is a `create` keeping the earliest `before`, which collections treat as a move; updates union their fields. A dispatcher runs its flushes' sinks in revision order, so frames for one row never arrive out of order; a sink failure does not block the next flush.
2. Take a revision: a whole number of microseconds since the epoch (a safe integer, about 1.8e15), per process `max(Date.now() * 1000, last + 1)`; behind a cluster the shared counter's `max(last + 1, Valkey TIME in µs, this node's last + 1)`, which stays on Valkey's clock below a million flushes a second (pack H). `versionColumn` times compare as milliseconds × 1000. The revision is taken before any row is read, so a payload is never older than its revision claims; behind a cluster each frame is decided by its row as read at flush time, since a write that committed first can flush last.
3. Expand `affects` one hop, without duplicates.
4. Per service and projection that has subscribers, read the touched rows in one query.
5. Emit entity frames, collection deltas and change signals (sections 6, 7, 11.3).

A flush failure is logged with the affected rows and emits a `reset` to the touched collection scopes. It never fails the already-sent response.

### 5.4 Storage adapter

`./prisma` exports `trackPrisma(client, options)`, which returns the client itself carrying its adapter (`storageOf(db)` on `./server`); apply it as the last extension, because extensions added after it do not run on interactive-transaction clients. Passing the tracked client as `db` to `createServer` / `createDispatcher` is all an app does. The server depends only on a structural interface: `findMany(model, { where, select, orderBy, take })`, `count`, `registerInterest`, `onWrite` and `countStatements`. Drizzle support is a second implementation of that interface.

## 6. Projections and entity subscriptions

- A projection's schema keys determine the `select`. `Date` values become ISO strings. Rows are never loaded wider than the projection.
- A projection that needs relations or computed fields declares them: `project: { card: { select, map } }` on the service. `map` is synchronous and pure.
- Entity rooms are per tier: `qd:e:{service}:{id}@{level}`. A subscriber joins the room for its level. A frame is built once and stripped once per occupied tier. A shared run's reply (section 9, step 6) is stripped and JSON-encoded once per group of callers whose levels hide the same fields on every row (`SharedData`), and every caller in a group receives the same bytes. The other rooms: `qd:c:{service}:{collection}:{scope}` for a collection scope, `qd:t:{service}:{topic}` for a change topic, and `user:{userId}` for a user (unchanged from 4.x). The helpers live in `contract/names.ts`.
- Frames, all on the single event `qd:e`:

| `t` | Payload | Client action |
|---|---|---|
| `u` | full projection | replace when `rev` is newer |
| `p` | changed fields only | merge when `rev` is newer; request the row when it is not cached |
| `r` | none | remove; keep a tombstone until a newer `u` |

  A patch is sent when the write's changed fields are all plain projection fields; otherwise a full update.
- Subscribe is batched (`qd:sub` with an id list and the revisions held). The reply per id is the row, "not modified", or an error. The default batch cap is 500.
- Entity subscriptions carry revisions. 4.1 had none.
- "Not modified" is answered from the service's `versionColumn` when it declares one (for example `updatedAt`), or from the in-process change log when that covers the caller's revision. Otherwise the full row is sent.

## 7. Collections

A collection is the rows of one service grouped by a scope value.

### 7.1 Declaration

| Option | Meaning |
|---|---|
| `scope` | a column, or `via({ model, entry, scope })` for scopes that come from a junction table (a chat in each member's list) |
| `item` | projection name |
| `where` | equality filter that decides membership (`{ archived: false }`) |
| `order` | sort columns ending in `id`; used for the keyset cursor |
| `limit` | page size (default 100) and `maxLimit` (default 500) |
| `index` | small fields sent for the whole scope (section 7.4) |
| `views` | named predicates over index fields (section 7.5) |
| `access` | level required on the scope's anchor row; defaults to `Read` through the anchor's policy |

The row a scope is anchored on for access is declared server-side, in `defineService` (`collections: { byProject: { anchor: project } }`), because access policies live there and the contract carries none. A scope whose value is the subscriber's own user id declares `scopeAccess: "self"` instead of an anchor. A `via` scope names the junction model by its database name; that is the one place a contract carries a model name, accepted because the junction usually has no service of its own. A `scopeAccess: "self"` collection strips its items at `Read` and may not declare a higher `access`. When a collection declares `index`, every `order` column but `id` must be an index field, so a client can keep the index in order from deltas. No `order` column may be tiered above the collection's `access`, with or without an index: a page's cursor and order would tell subscribers what it holds. Collection names may not contain `:` (topic strings split at the first colon).

Scope membership is declared, not computed by a function, so the framework knows which writes can move a row and skips the pre-read for all others.

### 7.2 Deltas

All on the single event `qd:c`, batched per flush: `{ s, c, scope, rev, deltas }`.

| Type | Payload |
|---|---|
| `added` | item, and its index row |
| `updated` | full item |
| `patched` | id and changed fields |
| `removed` | id |
| `reset` | none; the client re-snapshots after a random 100 to 2,000 ms |

- Create emits `added`; an update that stays in scope emits `patched` or `updated`; a move emits `removed` then `added`.
- A flush touching more than `bulkThreshold` rows of one scope (default 200) emits one `reset`.
- Junction writes on a `via` scope add or remove the item for that scope only.
- When the row a scope is anchored on is deleted (a chat, for its messages), the framework sends `qd:revoked { kind: "collection", reason: "anchor-deleted" }` to every collection scope room keyed by that row and empties those rooms. Child rows removed by a database cascade therefore need no deltas of their own.
- Items are visible to everyone in the scope. There are no per-subscriber field tiers inside a collection.

### 7.3 Snapshot, paging and resume

- `qd:col:sub { s, c, scope, since?, limit?, cursor? }`.
- Without `since`: authorize, join the room, return the first page, the total count, the next cursor, and the index when declared.
- With `since`: if the server's recent-delta buffer for the scope (500 entries or 5 minutes, per process) covers that revision, reply `{ resumed: true, deltas }`. Otherwise reply with a snapshot.
- Cursors are keyset cursors over `order`. A request above `maxLimit` is clamped, and the response says so.

### 7.4 Index and whole-scope loading

When `index` is declared, the first snapshot includes one small row per member of the scope: `[id, rev, ...index fields]`, capped at 50,000 rows. The client then knows full membership and order immediately, can prune without an id cap, and loads full items by window, by id list (`qd:col:items`), or all at once (`load: "all"` pulls pages until done). Deltas keep index rows and items consistent.

### 7.5 Views

A view is a named pure predicate in the contract, evaluated on the client over index rows: `(row, who) => boolean`. `useCollection(scope, { view: "mine" })` returns the matching members. Because the whole index is present and live, views need no mirrored server filter. A predicate may read only `id` and index fields; this is checked by type.

## 8. Protocol v5

A `Revision` is a whole number of microseconds since the epoch, a safe integer; clients compare revisions as ordered numbers and never read them as times (pack H; before, milliseconds). An index row's `versionColumn` revision is in microseconds too.

Not wire-compatible with 4.x.

### 8.1 Handshake

The client connects with `auth: { token, qd: { protocol: 5, client: "<version>" } }`. The server replies with `qd:hello { protocol, server, limits, features }`. A client with a different protocol is refused with `PROTOCOL_MISMATCH` in the connection error's data (a handshake refusal, not one of the error codes in section 3); the v5 client calls `onProtocolMismatch` (default: reload once per session).

### 8.2 Client to server

| Event | Payload | Reply |
|---|---|---|
| `qd:call` | `{ id, s, m, i, v? }` | `{ ok: true, d, v? }`, `{ ok: true, nm: true, v }` or `{ ok: false, e: { code, message, data? } }` |
| `qd:cancel` | `{ id }` | none |
| `qd:sub`, `qd:unsub` | section 6 | per-id results |
| `qd:col:sub`, `qd:col:unsub`, `qd:col:items` | section 7 | snapshot, resume or items |
| `qd:watch`, `qd:unwatch` | `{ s, topic }` | ok |
| `qd:stream:sub`, `qd:stream:unsub` | section 12.5 | seed |
| `qd:ch` (volatile) | one array argument `[s, channel, payload]` | none |

The field names of every frame are defined by `packages/core/src/protocol/envelope.ts`, which is normative; where this document omits a name, the code wins. A call `id` is a non-negative safe integer; `v` is a number or a string. The unsubscribe events (`qd:unsub`, `qd:col:unsub`, `qd:unwatch`, `qd:stream:unsub`) take an optional `Ok | Failure` acknowledgement.


Subscription events (`qd:sub`, `qd:col:sub`, `qd:col:items`, `qd:watch`) are exempt from the per-socket rate limiter and run in a per-socket lane instead (`limits.subscriptions`, default 8 in flight and 64 queued, then `RATE_LIMITED`; waiting work is dropped on disconnect). Unsubscribe and unwatch events need a principal, name a served service or collection (`NOT_FOUND` otherwise), take at most 500 ids, and scope and topic strings are at most 256 characters; bookkeeping for an unsubscribe is kept only while a subscribe of that key is in flight. Per-socket records are keyed without prototypes, so frames naming `__proto__` or `constructor` are ordinary misses.

### 8.3 Server to client

`qd:hello`, `qd:e`, `qd:c`, `qd:changed`, `qd:revoked`, `qd:stream`, `qd:event` (typed custom room events), `qd:rotate` (reconnect within a jitter window; for platforms that cap connection lifetime), `qd:access` (updated service grants).

The client registers one listener per event and routes by key. It does not register one listener per entity or scope.

### 8.4 Parser

A JSON-only Socket.IO parser on both ends: no recursive binary scan, each packet serialized once, and the byte length reported to the pipeline. Its output is byte-identical to the stock parser for packets without binary, so the legacy shim needs no second parser. Apps that send binary pass `binary: true` and get the stock parser. The JSON parser refuses binary only at the top level of a packet's arguments; a binary value nested inside a method's input or output is not detected and would be serialized as plain JSON. A deep check costs two to six times the encoding time and is therefore not a default; it may be offered as a development-mode option later.

### 8.5 Legacy shim

`legacyWire: true` attaches one `socket.use` middleware, registered after the rate limiter, for sockets that connect without `auth.qd` (not `onAny`, which Socket.IO runs before middleware and would let 4.x calls bypass the limiter). It maps a 4.x `"{service}:{method}"` event with an ack onto the dispatcher and answers in the 4.x `ServiceResponse` shape. It does not serve subscriptions, collections or channels. It logs each legacy caller once so the remaining ones can be found.

## 9. Method pipeline

Per call, in order:

1. Look up the method. Unknown gives `NOT_FOUND`.
2. Concurrency: at most 16 queries in flight per socket, a queue of 64, then `RATE_LIMITED`. Mutations are not queued behind queries. A slot is held until the work the call started settles (its handler, or the stage it was waiting on), even after the caller was answered by a cancel or a timeout. The time limit starts at admission and covers validation, access checks, `version()`, the handler and the output check; queue time does not count.
3. Validate input.
4. Authorize (section 4).
5. Not modified: for a query whose output is a single projection row, compare the caller's `v` with the row's revision. Other queries may declare `version(input, ctx)`.
6. Share: a query may declare `share: "caller"` (identical concurrent calls by one principal run once) or `share: "all"` (shared across principals; allowed only when access is not `custom`). Optional `ttlMs`. The `"caller"` key covers the principal, `ctx.transport` and `ctx.mcp`, written by a strict serializer: a principal or input with function members, symbols, getters or any non-plain object (except `Date`) makes the call run unshared. Field tiers are applied per caller after a shared run, never inside it (section 6). A schema output is sent as the handler returned it, in every mode: output validation checks but never strips, so projections are the mechanism for keeping fields off the wire.
7. Run the handler inside a unit of work, with the abort signal and a time limit (default 30 s). A mutation ignores the caller's cancel signal; only the time limit aborts it, because abandoning a write mid-flight is worse than finishing it. A shared run's handler sees the first caller's `ctx`.
8. Validate output in development and test.
9. Respond, flush, and emit one completion record: service, method, kind, outcome, duration, queue time, bytes, shared, SQL statements.

Logging: one structured record per call at debug level. Server faults (`INTERNAL`, `TIMEOUT`) log at error; client-caused failures (`FORBIDDEN`, `VALIDATION`, `NOT_FOUND`, `UNAUTHENTICATED`, `RATE_LIMITED`, `CANCELLED`) log at debug; calls slower than `slowMs` (default 1,000) or larger than `maxResponseBytes` (default 1 MiB) log at warn. A full queue answers `RATE_LIMITED` with `retryAfterMs` of 1,000 by default. `custom(fn)` access requires a principal; a method open to anonymous callers uses `"public"`.

### 11.1 Provider

`<QuickdrawProvider client={qd} url auth />` owns the socket. It exposes Socket.IO manager options, handles `qd:rotate`, `qd:access`, protocol mismatch, and rate-limit backoff with jitter. It works without DOM globals (React Native).

### 11.2 Calls

Queries pass TanStack's abort signal through as `qd:cancel`. A timed-out query is not retried by default. Errors are `QuickdrawError` instances with a `code`.

### 11.3 Invalidation

- A coordinator per `QueryClient`: one read in flight per key; an invalidation during a read marks it dirty and runs exactly one follow-up when it settles; an in-flight read is never cancelled by an invalidation.
- A query with `watch` joins that topic. The topic string is `{collection}:{scopeId}` with the scope id from `watch.scope(input)`, or `service` for the service-wide topic. The service topic is closed unless the service declares `watchAccess` (`"public" | "authenticated" | { service }`): without it `qd:watch` on `service` is `FORBIDDEN` for everyone, so a signed-in user never learns when another tenant's rows change. The server sends `qd:changed` once per flush; the coordinator invalidates.
- After a reconnect, entity and collection subscriptions resume by revision. Only watched or stale queries are invalidated, after a random delay of up to `reconnectJitterMs` (a provider option, default 2,000 ms; `jitterMs` on `refetchAfterReconnect`; 0 refetches at once).

### 11.4 Mutations

`useMutation` returns the TanStack mutation. A mutation whose input has `id` and whose output is `"entity"` is optimistic by default: matching input fields are overlaid on the cached entity and on collection items with that id, rolled back on error, and dropped when a frame with a newer revision arrives. `optimistic: false` opts out; `optimistic: (input, cache) => {...}` customizes.

### 11.5 Live data

- Entity cache key `["qd", service, "e", id]`; collection key `["qd", service, "c", name, scope]`; query key `["qd", service, "m", method, input]`.
- Collections refresh by resume when the tab becomes visible after 30 s hidden, and run a resume check every 5 minutes with jitter.

## 12. Kits

A kit adds contract entries and handlers with one line each. All use the same pipeline, access and emit paths.

### 12.1 Read/write

`get`, `getMany` (id list, max 200), `list` (keyset cursor, `accessWhere` applied, filter and sort restricted to declared fields, hard limit), `create`, `update` (partial), `delete`, `reorder`, `bulkUpdate`, `bulkDelete`. Each is opt-in by name and takes an `access` form.

### 12.2 Search

Declared fields; case-insensitive contains by default; an adapter hook for Postgres full-text search. Results are access-filtered lean items with a keyset cursor. `useSearch` debounces, cancels superseded calls, and its results stay live through the shared item cache.

### 12.3 Sharing and membership

For `jsonAcl`: `share`, `unshare`, `setLevel`, `listShares`. For `members`: `invite`, `remove`, `leave`, `setRole`, `listMembers`. Changes go through tracked writes, so revocation and `via` scopes update without extra code.

### 12.4 Admin

Typed admin methods with field metadata derived from the entity schema, and `qd.admin.*` client hooks.

### 12.5 Presence and streams

- Presence: online state per user across sockets, last seen, room occupancy; `usePresence`.
- Streams: server-to-client append-only data with a seed (`stream.push(scope, item)`, `useStream`), optional volatile delivery.
- Channels (client-to-server fire-and-forget with a per-socket token bucket) carry over from 4.1, declared in the contract.
- Contract shapes: `channels: { <name>: { payload, ratePerSecond?, burst?, requires? } }`, `streams: { <name>: { item, scope?, seed?, volatile?, access? } }`, `events: { <name>: { payload } }`. The contracts card shipped the minimal `{ payload }` and `{ item }` forms; the presence-and-streams card extends the contract types with the remaining options.

### 12.6 Auth routes

Google, Discord, mock and guest providers, session store, cookie and JWT handling, mounted on the app's Express app.

- **Collections card (pack C, child 4), 2026-10-02.** The service declares `collections: { [name]: { anchor } | { scopeAccess: "self" }, bulkThreshold? }` (required when the contract has collections; `bulkThreshold` lives there, default 200). ## 18. Spike results (2026-10-02)

A throwaway script (`track.ts`, attached to the tracked-writes card) exercised section 5 against Prisma 7.4.2 with PGlite 0.3.16 under Bun 1.3.13, using quickdraw-chat's generated client.

Confirmed:

- A `query.$allModels.$allOperations` hook sees writes on the root client and on the client passed to an interactive transaction.
- `AsyncLocalStorage` set around the transaction callback is visible inside the hook, so the hook can find the transaction client for pre-reads.
- Interactive transactions: commit merges the buffered records; rollback discards them.
- Array-form `$transaction([...])` writes are seen when the scope is established around the `$transaction` call.
- `updateMany` and `deleteMany` ids can be captured by a pre-read through the transaction client.
- `createManyAndReturn` and `updateManyAndReturn` exist and work on PGlite.
- `$transaction` can be overridden through a `client` extension; a `Proxy` around the client also works.
- The hook can count operations per scope, and fires with no scope active.

Confirmed gaps, all handled in section 5.2:

- A `create` whose `select` omits `id` returns no id; the adapter must add it.
- Nested writes reach the hook only as the parent operation.
- Database cascades produce no hook call.

Found by the spike:

- A Prisma promise returned from the scope and awaited outside it is not tracked (section 5.1). The unit of work must await inside the scope.

Also checked: the installed `socket.io-parser` 4.2.5 `Encoder.encode` calls `hasBinary` and then `encodeAsString`. A JSON-only encoder is the stock `Encoder` with `encode` overridden to return `[this.encodeAsString(packet)]`, which is byte-identical by construction.
